# Directional inversion, not missing knowledge, is the dominant failure mode

Day 1's baseline (12 items, 38%) showed that Jayroop reliably knows *which concepts exist* and reliably gets *which way round they go* wrong: GINI max↔min, precision↔recall (three separate attempts), cross-entropy high↔low on matching pixels. Coverage is not the problem — direction is.

**Evidence.** His own handwritten margin notes on the Tagged IntroML PDFs contain the correct statements for both GINI and precision/recall; he wrote them correctly months ago and retrieved them backwards today. That rules out "never learned it" and points squarely at storage strength: annotation is recognition, retrieval is not.

**Implications for future sessions.**
1. Re-reading decks will feel productive and change nothing. Weight every window toward cold retrieval.
2. When the same item fails twice from *different* angles (as FP-4 did), stop testing and re-teach the encoding — a third test just rehearses the error. Teach an anchor, then resume retrieval on a later day.
3. Prefer question forms that force a *direction* to be committed: which pole, which denominator, which metric moves when this error type increases. These expose the fault that open-ended explanation hides.
4. A related habit (FP-7): asked to *name* a principle he supplies a famous neighbour — bias-variance for Occam's Razor, MLE for empirical risk minimisation. Name-the-principle items every window, exact term required.
